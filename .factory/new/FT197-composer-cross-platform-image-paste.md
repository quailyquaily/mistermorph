### Goal and scope
Actual clipboard IMAGE paste must work in the chat composer on Web, native desktop, Android app and iOS app. Text paste, file dragging, gallery selection, or a browser working instead of the native apps does not satisfy this requirement. Keep one cross-platform item because the composer/attachment pipeline is shared. Reuse FT195/FT110 upload, pending pills, previews, retry, removal, scope guards and send file_references; do not create a parallel upload protocol. Existing paste code is a starting point, not evidence of working behavior on all devices.

### Required interactions
1. A user-triggered image-only paste into an eligible focused composer creates a visible pending image attachment without sending or starting a task. Cover empty/non-empty drafts, new/existing conversations and preserve text/caret behavior.
2. Web: handle real browser paste/clipboard file data, without background polling or an unnecessary navigator.clipboard.read permission. Desktop: Ctrl/Cmd+V and available Edit/context-menu Paste. Android: long-press system Paste with image content on supported versions (reported minimum API26); API31+ receive-content/compatible keyboard image actions such as Gboard clipboard chips use the same flow. Do not promise API31 keyboard behavior on API26-30. iOS: native edit-menu Paste must accept an image-only clipboard in empty and populated composers; respect system paste consent/denial. A new button does not substitute for working mobile system Paste.
3. Preserve image order within a paste and rapid repeated pastes despite reversed async read/conversion/upload completion; prevent duplicate native/paste-event ingestion. Mixed text/image inserts text and attaches images when both are delivered; ordinary text paste is unchanged. Document actual host limitations such as macOS/Wayland text-first mixed clipboard behavior. File-manager URI/directory paste is not required.
4. Reuse authenticated upload, local/remote endpoint semantics and workspace binding. Guard endpoint/topic/draft scope during async work and release stale results. Preserve FT195 composer-only drop targeting, modal isolation and workspace behavior.
5. If editing/sending/no endpoint or other attachment restrictions prevent attaching an image, preserve the draft and show an actionable reason when an image paste event is delivered. Todo remains text-only. If the native platform denies/consumes paste before JS, record that boundary accurately and use native feedback where feasible; do not pretend a JS notice occurred.

### Formats, limits, privacy and errors
- Validate bytes/type using safe existing helpers, not only generic names/MIME. Correct known mismatches; reject corrupt/unknown content visibly instead of uploading non-PNG bytes as PNG. Never render SVG/HTML as active content or fetch clipboard URLs/paths as implicit network/local-file permission.
- PNG/JPEG/WebP within effective limits must work end-to-end. For GIF/BMP/TIFF/HEIC use an actually available proven conversion, or safely attach as an ordinary file with an explicit not-directly-model-visible warning, or reject with supported formats listed. Never silently omit/falsely label images. Check resulting type/size after iOS HEIC-to-PNG conversion. Automatic compression is not required.
- Distinguish 64 MiB upload allowance from 5 MiB-per-image/3-image model allowance. Check size before upload when available, retain server enforcement and bound native reads before excessive allocation where runtime changes permit. Default: validate/explain model-ineligible images BEFORE sending, preserve text/attachments for removal/resizing, and do not knowingly start a task destined to fail for image limits. Ordinary-file fallback requires explicit visible semantics and backend tests. Do not silently raise limits or redesign other channels. Handle version-dependent remote server refusal without losing the draft.
- Clipboard reads must be user-triggered. Respect temporary Android content URI grants/iOS consent; no broad storage/photo-library/background clipboard permission just to paste. Do not log image bytes, private URI paths or tokens. Reuse existing authorization/path-reference validation.
- Cover empty clipboard, ordinary text, expired/unreadable URI, denied access, read/conversion failure, zero-byte/corrupt data and upload/network/auth failures. Preserve draft/unrelated attachments. Retry only while bytes/grants remain available; otherwise explain that repaste is needed. Release temporary files/object URLs/native resources through existing lifecycle patterns.

### Native boundaries
Verify pinned nsh 0.6.0/GPUI dependencies and actual packaged mobile runtime versions. Prefer application integration/existing bridges. Narrow vendor/native overrides or a pinned dependency update are allowed only for demonstrated missing capability, with reproducible packaging/licensing and focused tests. Android already overrides runtime classes via web/console-nsh/scripts/android-host.sh: verify that mechanism before use. iOS sources are external/prebuilt; identify the exact missing capability/version and upstream or packaging remedy if a fix is needed, never invent an API. Do not drop a platform or claim it accepted from source inspection alone. Missing devices are unverified coverage, not fabricated success; automated implementation need not wait for unavailable hardware.
